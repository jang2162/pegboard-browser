## Q1. Chromium 포크 시점 (결정됨)

**결정 (2026-11-10)**: 로컬 MVP 다음에 포크한다. 0~2단계는 순정 Chromium과 작은 확장 프로그램으로 진행하고, 포크는 3단계에서 시작한다. 확장 프로그램 판 브리지는 3단계에서 내장 브리지로 바꾸며 버린다.

## Q2. 프로필과 로그인 상태 공유 (결정됨)

**결정 (2026-11-10)**
- 일상용으로도 쓴다. 사람과 에이전트 사이는 프로필로 격리하고 공유하는 것은 없다.
- 에이전트 세션끼리는 에이전트 프로필 하나를 공유한다. 쿠키와 로그인 상태가 세션 사이에 공유된다.

- 공유가 기본이되, 필요하면 CLI로 이름 있는 프로필을 만들거나 기존 프로필을 복사한 임시 프로필로 세션을 열 수 있다.

근거와 감수하는 점은 architecture.md 결정 6과 6절 "에이전트 프로필".

## Q3. 대상 OS와 순서 (결정됨)

**결정 (2026-11-10)**: macOS가 먼저다. macOS Developer ID가 있어 서명과 공증이 바로 가능하다. Windows는 코드 서명 인증서가 없어 뒤로 미룬다.

작성자가 채운 부분: macOS 안에서는 arm64를 먼저 하고 x64는 필요할 때 추가한다. macOS 다음은 Linux, 그다음 Windows(인증서 확보 후)로 둔다. 원격 머신의 OS가 정해지면 이 순서를 다시 본다.

## Q4. 에이전트 기본 권한 (결정됨)

**결정 (2026-11-10)**: 대부분 허용하고 일부만 확인한다. 탐색, 클릭, 입력, 스크립트 실행, 다운로드는 바로 된다. 파일 업로드, 쿠키와 저장소 쓰기, 네트워크 요청 가로채기는 승인을 기다린다. 표는 architecture.md 11절.

엄격 모드(스크립트 실행과 다운로드도 확인, 도메인 허용목록 필수)는 세션이나 프로필 단위로 고를 수 있는 선택 사항으로 둔다.

탭 넘겨주기는 프로필 격리 결정으로 없어졌다.

## Q5. 원격 머신의 종류 (결정됨)

**결정 (2026-11-10)**: 화면이 있는 데스크톱. 릴레이는 로그인한 사용자의 세션에서 돌고 브라우저 창이 실제 화면에 뜬다. 화면이 없는 서버는 7단계의 후보로 남긴다.

원격 머신의 OS와 대수는 아직 모른다. Q3에 영향을 준다.

## Q6. 동기화 범위 (결정됨)

**결정 (2026-11-10)**
- 비밀번호 저장은 브라우저에 구현하지 않는다. 확장 프로그램(Bitwarden, 1Password 등)에 맡긴다.
- 그 밖의 항목은 크롬처럼 동기화한다. 북마크, 방문 기록, 열린 탭, 환경설정, 확장 프로그램.

구현 방향(Chromium 동기화 엔진 재사용, 서버만 교체)과 비용은 architecture.md 결정 7. 로드맵 6단계로 넣었다.

## Q7. 녹화 용도와 기본값 (결정됨)

**결정 (2026-11-10)**: 녹화의 주된 용도는 디버깅이다. 에이전트가 무엇을 했는지 되짚어 보는 데 쓴다.

이에 따라 제안값을 그대로 쓴다. 동작 로그와 화면을 기본으로 켜고, 14일이 지났거나 전체 5GB를 넘으면 오래된 것부터 지운다. 변조 방지와 장기 보존은 하지 않는다. 숫자 14일과 5GB는 작성자가 고른 출발점이고 설정으로 바꿀 수 있다.

## Q8. 서버 운영 형태, 계정 범위, 종단 간 암호화 (결정됨)

**결정 (2026-11-10)**
- 운영 형태: 직접 띄우는 서버 하나. 단일 바이너리와 컨테이너 이미지로 제공한다.
- 계정: 개인 계정만. 팀과 역할은 7단계 후보로 남긴다.
- 원격 제어 터널의 종단 간 암호화: 메시지 형식만 대비하고 구현은 미룬다. 서버가 본인 것이기 때문이다.
- 브라우저 동기화 자료는 암호화해서 올린다(결정 7).

## Q9. 인력과 업스트림 추적 주기 (결정됨)

**결정 (2026-11-10)**
- 혼자 개발한다.
- Extended Stable을 따라간다(약 8주 주기로 기억하며, 3단계 전에 다시 확인한다). 그 사이의 보안 수정 릴리스는 따로 따라간다.

작성자가 채운 부분: 보안 수정 릴리스는 나온 뒤 7일 안에 반영하는 것을 목표로 하고, 넘기면 브라우저에 구버전 경고를 띄운다. 7일은 근거 있는 숫자가 아니라 출발점이다.

## Q10. 배포 방식과 공개 여부 (결정됨)

**결정 (2026-11-10)**
- 본인이 쓰는 것이 목적이지만 배포 구성까지 만든다. macOS Developer ID 보유.
- 저장소는 공개한다. 라이선스는 MIT.

작성자가 채운 부분: 자동 업데이트 파일은 깃허브 릴리스에 둔다. Windows 코드 서명 인증서는 Windows를 지원할 때 마련한다.

## Q11. 모델 연동의 사용 사례 (보류)

사용자가 구상으로 낸 기능이다. 브라우저에 모델(API 키, Ollama, LM Studio)을 연결하고, Jev 같은 결정 모델로 제어를 빠르게 하는 것. 구조 초안과 판단은 architecture.md 13절.

일정을 잡지 않았다. 구체화하려면 필요한 것:
- 어떤 일을 빠르게 하고 싶은가. 반복 작업이면 모델 없이 저장된 흐름으로 충분할 수 있다.
- Jev를 로컬에서 돌릴 수 있는지, 라이선스와 과금. 지금은 검색 요약만 본 상태다.
- 2단계 뒤에 실제 작업으로 시간, 토큰, 성공률을 재 보는 실험을 할 것인가.

## Q12. 북마크 프로필의 동작

사용자 요구(2026-11-11): 브라우저 프로필 하나에서 북마크 묶음을 여러 개 쓰고, 북마크바 왼쪽 선택기로 바꾼다. 설계 제안은 architecture.md 14절.

**(가) 선택의 범위 (결정됨, 2026-11-11)**: 브라우저 프로필 전체. 고르면 그 프로필의 모든 창에서 북마크바가 함께 바뀐다. 창마다 다르게 두는 것은 하지 않는다.

**(나) 주소창 제안과 검색**: 모든 북마크 프로필의 북마크가 나온다(제안) / 현재 선택된 것만 나온다. 뒤쪽은 주소창 제안 코드까지 고쳐야 한다.

**(다) 선택의 동기화**: 기기마다 따로 기억한다(제안) / 기기 사이에 맞춘다.

**(라) 화면에 쓸 이름**: "북마크 프로필"은 브라우저 프로필과 겹친다. 후보: 북마크 세트, 북마크 모음, 스페이스.
