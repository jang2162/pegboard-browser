# 2b단계 설계: 화면 녹화와 재생 (블랙박스)

- 작성일: 2026-11-17
- 상태: 사용자 승인 (2026-11-17)
- 기반: [architecture.md 8절](../architecture.md#8-녹화), [roadmap.md 2b](../roadmap.md)
- 이 문서에서 "사용자 결정"은 사용자가 고른 것, "제안"은 작성자가 정한 것이다. 제안은 사용자가 고칠 수 있다.

## 1. 의도

녹화는 **자동차 블랙박스**다(사용자, 2026-11-17). 평소에는 신경 쓰지 않아도 늘 켜져 있고, 오래된 것부터 저절로 지워지고, 무슨 일이 생겼을 때만 꺼내 본다. 보는 사람은 사람이다. 주된 용도는 디버깅이다(사용자 결정, 2026-11-10).

지금(2a까지)은 동작 기록(`actions.jsonl`)만 남는다. 텍스트로는 "클릭이 실패했다"는 알 수 있지만, 그때 화면에 무엇이 떠 있었는지, 명령과 명령 사이에 페이지가 어디로 넘어갔는지, 사람이 무엇을 눌렀는지는 알 수 없다. 2b는 여기에 화면을 붙이고, 사람이 그것을 쉽게 되짚을 재생 화면을 만든다.

## 2. 목표, 하지 않는 것, 실패 조건

**목표**
- 세션을 만들면 설정 없이 화면 녹화가 시작된다.
- 모든 명령의 직전·직후 화면이 반드시 남는다. 명령 사이의 화면 변화도 남는다.
- `pegboard recording open <id>`로 재생 화면이 열리고, 실패·정책 거부·사람 개입이 시간축에 표시되며, 누르면 그 시점 화면으로 간다.
- 오래된 녹화는 저절로 지워지고, 사람이 표시한 것만 남는다.

**하지 않는 것 (2b 범위 밖)**
- 동영상 내보내기(`recording export --format webm`). ffmpeg가 필요하고, 블랙박스 용도에는 재생 화면으로 충분하다(제안). 필요해지면 따로 넣는다.
- 에이전트에게 화면을 돌려주는 것. 에이전트는 지금처럼 텍스트 동작 기록(`recording show`, `pegboard_recording_get`)만 본다(제안: 보는 사람은 사람).
- 변조 방지(서명, 해시 사슬). 디버깅 용도라 하지 않는다(사용자 결정, 2026-11-10).
- 원격 녹화 열람(5단계), 실시간 화면 보기(5단계).
- 사람의 탭이나 다른 앱의 화면. 세션 탭만 찍는다.

**실패 조건 (동작해도 이렇게 되면 실패)**
- 녹화 때문에 에이전트 명령이 눈에 띄게 느려진다. 기준은 4.6절.
- 사람 프로필의 탭이 한 장이라도 찍힌다.
- 녹화가 디스크를 끝없이 채운다(보존 한도를 넘는다).
- 재생 화면이나 녹화 파일에 에이전트 세션이 닿는다(에이전트가 다른 세션의 화면을 보거나, 재생 서버를 통해 데몬에 닿는다).
- 화면 기록을 끈 도메인의 화면이 남는다.
- 동작 기록에서 가린 값이 재생 화면의 동작 목록(텍스트)에서 드러난다. 화면 프레임은 여기에 들지 않는다(R10): 카드 번호·일회용 코드 입력란의 숫자, 사람이 에이전트 창에서 직접 로그인하는 과정, "비밀번호 보기"를 누른 화면은 그대로 찍힌다. README 알려진 한계에 적는다.

### 접근 방식 (R3)

- **A. 바뀔 때마다 + 동작마다 반드시 (선택).** Chrome의 화면 스트림(`Page.startScreencast`)으로 바뀐 화면을 받되 초당 2장으로 묶고, 명령 앞뒤에 직접 한 장씩(`Page.captureScreenshot`) 찍는다. 명령 사이의 변화와 실패 앞뒤 화면이 모두 남는다.
- **B. 동작마다만.** 가장 가볍지만 명령 사이(자동 이동, 팝업, 사람 개입)가 비어 블랙박스 목적에 어긋난다.
- **C. 일정 간격.** 멈춘 화면이 중복으로 쌓이고 짧은 화면을 놓친다. A, B보다 나은 점이 없다.

## 4. 설계

### 4.1 무엇을 기록하나

| 종류 | 기본 | 비고 |
|---|---|---|
| 동작 기록 | 켜짐 | 이미 있음(`actions.jsonl`). 항목에 직전·직후 프레임 이름을 더한다 |
| 화면 | 켜짐 | 세션 탭마다. 4.2절 |
| 탐색 기록 | 켜짐 | 탭별 주소 변화, 탭 열림·닫힘, 팝업. `navigation.jsonl` |
| 사람 개입 | 켜짐 | 4.4절 |
| 네트워크 메타데이터 | 꺼짐 | `--record network`. 주소, 상태, 크기, 시간. 헤더 `Authorization`, `Cookie`, `Set-Cookie`는 항상 가린다. 본문은 기록하지 않는다 |
| 콘솔 | 꺼짐 | `--record console`. 메시지와 페이지 오류 |

네트워크 본문 기록은 2b에서 만들지 않는다(제안: 민감 정보가 가장 많고 블랙박스 용도에 필수가 아니다).

### 4.2 화면 기록

- 데몬이 세션 탭마다 이미 유지하는 자기 CDP 세션(포커스 유지용, architecture.md 4절)에서 `Page.startScreencast`를 건다. 에이전트의 연결과 별개이며, 에이전트 쪽 필터는 `Page.startScreencast`를 지금처럼 거부한다.
- 받은 프레임은 JPEG로 저장하고 `index.jsonl`에 `{ts, file, url, width, height, kind}`를 남긴다. `kind`는 `change`(스트림) 또는 `before`/`after`(명령 앞뒤).
- 초당 2장을 넘는 프레임은 버리되, 마지막 프레임은 화면이 멈췄을 때 남긴다(멈춘 화면이 마지막 상태가 되게).
- **명령 앞뒤**: `run_command`가 명령을 실행하기 직전과 끝난 직후에 대상 탭을 한 장씩 찍고, 동작 기록 항목에 `frameBefore`, `frameAfter`를 넣는다. 찍기가 실패하거나 시간(제안: 1초)을 넘기면 프레임 없이 명령을 진행한다. 녹화가 명령을 막거나 실패시키지 않는다. `frameBefore`, `frameAfter`가 가리키는 파일은 없을 수 있다(4.5절).
- **화질과 크기 (제안, 측정으로 조정)**: JPEG 품질 60, 가로 최대 1280픽셀. "무슨 일이 있었는지 알아볼 수 있는 화질"(architecture.md 8절).
- **찍지 않는 것**: 사람 프로필의 탭(데몬이 붙지 않는다), 화면 기록을 끈 도메인의 탭(그 주소인 동안 프레임을 버리고 "화면 기록 꺼짐" 표시만 남긴다), 세션에 속하지 않은 탭.
- **가려진 탭**: 0단계부터 미확인(architecture.md 8절 "위험"). 포커스 유지와 lifecycle active가 걸린 탭에서 스트림이 오는지 첫 작업에서 잰다. 안 오면 명령 앞뒤 캡처(직접 찍기)만은 남도록 하고, 스트림 빈 곳은 재생 화면에 "화면 없음"으로 표시한다.

### 4.3 탐색 기록

세션 탭의 `Target.targetCreated`/`targetInfoChanged`/`targetDestroyed`와 주 프레임 탐색 이벤트로 `navigation.jsonl`에 `{ts, targetId, event, url, opener}`를 남긴다. 주소는 동작 기록과 같은 규칙(`url_for_log`: 쿼리와 계정 정보 제거)으로 줄인다.

### 4.4 사람 개입

블랙박스에서 가장 중요한 "사고" 중 하나다. 세션 탭에서 **에이전트 명령이 실행 중이 아닐 때** 일어난 사용자 입력을 사람 개입으로 기록한다.

- 방법(제안, 측정 필요): 데몬의 세션에서 페이지에 입력 이벤트 감지기를 넣는 대신, 명령 실행 구간 밖의 탐색·탭 활성화·포커스 변화를 사람 개입 후보로 본다. 페이지 스크립트를 넣는 방법은 클립보드 방어(2a 작업 7)와 같은 경로를 쓰므로 가능하지만, 사이트 동작에 영향이 없는지 재야 한다. 어느 방법이 되는지 첫 작업에서 측정하고, 확실히 알 수 없는 신호는 "사람 개입 가능성"으로 표시한다.
- 기록: `actions.jsonl`에 `{"kind":"human", ts, targetId, what}` 항목.

### 4.5 저장 형식

architecture.md 8절의 구조를 따른다.

- 동작 기록의 `frameBefore`, `frameAfter`는 그 파일이 끝내 생기지 않은 프레임을 가리킬 수 있다: 디스크에 쓰지 못했을 때, 그 직후 캡처가 녹화 하나의 한도를 넘겼을 때, 세션이 끝날 때 writer가 제한 안에 끝내지 못했을 때(명령은 파일 쓰기를 기다리지 않는다, 4.6절). 보존 정리로 화면이 지워진 녹화도 같다. 읽는 쪽(보존, 재생 화면)은 없는 파일을 "화면 없음"으로 다룬다.

```
<PEGBOARD_HOME>/recordings/<recordingId>/
  manifest.json        + keep(bool), screen(bool), 크기 합계
  actions.jsonl        + frameBefore, frameAfter
  navigation.jsonl
  screen/<targetId>/index.jsonl, 000001.jpg ...
  network.jsonl        --record network 일 때만
  console.jsonl        --record console 일 때만
```

디렉터리 권한은 소유자 전용(0700, 파일 0600). 형식 버전을 `manifest.json`에 올린다.

### 4.6 성능 기준

- 명령 하나에 녹화가 더하는 시간: 중앙값 **60ms 이하**(소유자 결정 2026-11-18, 처음 제안은 50ms), 최악 **1초**.
- 측정: 첫 작업에서 녹화를 켜고 끈 상태로 1단계 호환 표의 명령들을 돌려 비교한다. 넘으면 해상도·장수를 낮추고, 그래도 넘으면 사용자에게 보고한다.
- 측정 결과(작업 1, 녹화기 흉내, 배율 1 화면): 명령 앞뒤 캡처로는 14개 명령 중 12개가 중앙값 50ms를 넘었고, 직후 캡처만 하면 세 번 모두 지켰다(명령별 중앙값 20~48ms, 최대 90ms. 여유는 가장 좁을 때 2ms). 그래서 직전 캡처를 뺐다(소유자 결정, 2026-11-17): `frameBefore`는 그 탭에 마지막으로 저장된 프레임이다. 직후 캡처의 제한은 500ms이고, 제한을 넘긴 탭은 30초 동안(또는 스트림 프레임이 올 때까지) 찍지 않는다. 자세한 것은 spike-findings.md "2b단계 측정"의 S2, F7.
- 측정 결과(작업 4, 실제 녹화기, 2026-11-17, 두 번째 기계: 데스크톱 Mac, 화면 배율 1, 명령마다 20쌍): `e2e_recording`의 `recording_overhead_meets_the_targets`. 배포용 빌드와 디버그 빌드의 더해진 시간 중앙값(ms):

| 명령 | 더해진 시간 중앙값, 배포용 빌드 (ms) | 더해진 시간 중앙값, 디버그 빌드 (ms) |
|---|---|---|
| `open` | 44 | 40 |
| `snapshot -i` | 26 | 26 |
| `click` | 48 | 49 |
| `fill` | 51 | 48 |
| `type` | 51 | 54 |
| `press Enter` | 32 | 32 |
| `get url` | 36 | 34 |
| `get text` | 37 | 34 |
| `eval` | 32 | 34 |
| `scroll down 200` | 30 | 32 |
| `wait 100` | 31 | 29 |
| `screenshot` | 40 | 34 |
| `tab new` | 41 | 40 |
| `tab list` | 33 | 28 |
| 최대 (모든 명령) | 87 | 88 |

  Chrome의 직접 캡처가 명령마다 16~41ms(중앙값)를 차지하고, 파일 쓰기는 명령을 기다리게 하지 않는다(writer에 넘기는 데 0.1ms 이하). 50ms를 넘은 것은 `fill`, `type`(51~54ms)이었고, 화질과 크기를 낮춰도 캡처 시간은 거의 줄지 않으므로(작업 1 S2) 소유자가 기준을 60ms로 올렸다(2026-11-18). 자세한 것은 spike-findings.md "2b단계 측정"의 "작업 4".

### 4.7 보존

- 데몬이 시작할 때와 1시간마다, 그리고 녹화가 끝날 때 정리한다.
- 지우는 순서: 끝난 지 14일이 지난 것, 그다음 전체가 5GB를 넘으면 오래된 것부터. 진행 중인 녹화와 `keep`한 것은 지우지 않는다.
- **용량 한도(5GB)로 지울 때는 화면(`screen/`)부터 지운다** (제안). 동작 기록은 크기가 작고 에이전트가 `pegboard_recording_get`으로 되읽으므로 14일까지 남긴다. 화면이 지워진 녹화는 `recording list`와 재생 화면에 "화면 지워짐"으로 표시한다.
- 2b 이전에 만들어진 녹화(동작 기록만 있음)도 같은 14일 규칙을 따른다 (사용자 결정 R4가 녹화 전체에 대한 것이므로). 2b를 처음 켜는 날, 14일이 지난 기존 동작 기록이 지워진다. README에 적는다.
- 진행 중인 녹화 하나가 너무 커지는 경우(제안: 녹화 하나 1GB): 그 녹화의 화면 기록만 멈추고 동작 기록은 계속한다. 재생 화면에 표시한다.
- `keep`한 것은 한도에 세지 않는다. 쌓이면 사람이 지운다(`recording delete`). `recording list`에 전체 용량과 `keep` 용량을 보여 준다.
- 설정: `<PEGBOARD_HOME>/config.toml`의 `[recording] max_age_days`, `max_total_gb`, `max_per_recording_gb`, `screen_off_domains`. 설정 파일이 없으면 기본값.

### 4.8 재생 화면

- `pegboard recording open <id>`: 데몬이 루프백에 일회용 주소(`http://127.0.0.1:<임시포트>/r/<일회용 토큰>/`)를 열고, **사람의 기본 브라우저**로 연다(macOS `open`). 에이전트 프로필 창에서 열지 않는다.
- 정적 페이지 하나와 녹화 파일을 읽기 전용으로 내준다. 토큰은 열 때마다 새로 만들고, 그 녹화 하나에만 유효하며, 30분 뒤나 데몬 종료 시 사라진다(제안).
- 이 포트는 2a 주소 규칙의 "pegboard 자신의 포트"에 들어가 에이전트 세션에서는 닿지 않는다.
- 화면 구성 (사용자 확인, 2026-11-17):

```
┌ 세션 "조사" · 14:02–14:19 · 명령 42 · 실패 2 · 거부 1 ┐
│  ┌──── 화면 (그 시점의 탭) ────┐    동작 목록          │
│  │                             │    14:05 open         │
│  │                             │  ▶ 14:06 click ✗      │
│  │                             │    14:06 fill 🔒      │
│  └─────────────────────────────┘    14:07 거부 ⛔       │
│  [탭: example.com | 팝업]  ◀ 직전  직후 ▶   14:09 사람 개입 │
│  ──●────✗──⛔────●──────────●── 시간축 ───────────────  │
└──────────────────────────────────────────────────────┘
```

  - 열면 첫 사고(실패, 거부, 사람 개입) 위치에서 시작한다. 사고가 없으면 처음부터.
  - 시간축의 사고 표시를 누르면 그 동작의 직전 화면, 한 번 더 누르면 직후 화면.
  - 탭이 여럿이면 화면 아래에서 고른다.
  - 동작 목록의 값은 동작 기록 그대로(가린 값은 가린 채) 보인다.
  - 페이지에서 온 글(주소, 오류 문구)은 텍스트로만 넣는다(HTML로 해석하지 않는다).
- 외부 자원(스크립트, 글꼴)을 쓰지 않는다. 바이너리에 넣은 HTML/JS/CSS 하나.

### 4.9 명령

| CLI | MCP | 설명 |
|---|---|---|
| `recording list [--session S] [--failed] [--kept]` | `pegboard_recording_list` (기존) | 목록에 화면 유무, 크기, keep 표시를 더한다 |
| `recording show <id>` | `pegboard_recording_get` (기존) | 텍스트. 사람 개입 항목도 나온다. 프레임은 이름만 |
| `recording open <id>` | 없음 | 재생 화면 |
| `recording keep <id>` / `unkeep` | 운영자 모드만 | 보존 표시 |
| `recording delete <id>` | 운영자 모드만 | 진행 중이면 거부 |
| `recording prune [--dry-run]` | 없음 | 지금 정리 |
| `session create --record network,console` | 운영자 모드의 정책 / `pegboard mcp --record ...` | 선택 기록 켜기 |

MCP 기본 모드의 에이전트는 자기 녹화의 텍스트만 읽는다(2a와 같다). keep/delete는 사람의 일이라 기본 모드에 없다(제안).

## 5. 위험과 측정할 것 (첫 작업)

1. 가려진 탭·최소화된 창·다른 Space에서 스트림 프레임이 오는가. 화면 잠금 중에는.
2. 명령 앞뒤 캡처와 스트림을 같이 걸었을 때 명령 시간 증가(4.6절).
3. 사람 개입을 알아낼 수 있는 신호(4.4절).
4. 스트림이 클립보드 방어·가드·다운로드의 탭 붙잡기(2a)와 충돌하지 않는가. 데몬 세션 하나에 기능이 더 붙는다.
5. 30분짜리 세션 하나의 디스크 사용량.

측정 결과 목표를 충족할 수 없으면(예: 가려진 탭에서 프레임이 오지 않고 직접 캡처도 실패) 만들기 전에 사용자에게 보고한다.

## 6. 만드는 쪽에 맡기는 것

- JPEG 인코딩 위치(Chrome이 준 JPEG를 그대로 저장할지), 프레임 파일 묶음 방식.
- 재생 화면의 세부 모양과 키보드 단축키.
- 정리 작업의 정확한 주기.
- 위 "제안" 숫자들(화질, 크기, 시간 제한)은 측정에 맞춰 바꿀 수 있다. 바꾸면 이 문서에 적는다.

## 7. 끝나는 조건

- 자동 시험: 녹화 켜짐/꺼짐, 명령 앞뒤 프레임, 끈 도메인에서 프레임 없음, 사람 탭 프레임 없음, 보존 정리(keep 제외), 재생 서버 토큰(다른 녹화·만료 토큰 거부), 에이전트 세션에서 재생 포트 거부, MCP 기본 모드에 keep/delete 없음.
- 성능 기준(4.6절) 측정 결과가 문서에 있다.
- 수동 확인: 재생 화면을 사람이 열어 사고 위치로 이동해 보는 것, 가려진 창·화면 잠금 중 녹화.
- README, architecture.md 8절, roadmap 갱신.
